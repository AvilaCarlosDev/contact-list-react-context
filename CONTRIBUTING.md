# Contribuir / Contributing

[Español](#español) · [English](#english)

## Español

Gracias por tu interés en mejorar `contact-list-react-context`.

### Desarrollo

```bash
npm ci
npm run lint
npm test
npm run build
```

### Principios

- Los cambios pequeños y enfocados se revisan más rápido.
- Todo cambio de comportamiento lleva pruebas.
- Nada de claves, tokens ni configuración privada en el código, los ejemplos o los issues.
- Mantén la documentación en español e inglés: si cambias una, actualiza la otra.
- Usa [commits convencionales](https://www.conventionalcommits.org/es/v1.0.0/) (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).

### Pull requests

1. Crea una rama desde `main`.
2. Ejecuta los comandos de la sección Desarrollo; deben pasar.
3. Abre el pull request y completa la plantilla. El CI debe estar en verde antes de fusionar.

### Reportar problemas

Abre un [issue](https://github.com/AvilaCarlosDev/contact-list-react-context/issues/new/choose). Para vulnerabilidades, sigue la [política de seguridad](SECURITY.md); no las publiques en un issue.

## English

Thank you for your interest in improving `contact-list-react-context`.

### Development

```bash
npm ci
npm run lint
npm test
npm run build
```

### Principles

- Small, focused changes get reviewed faster.
- Every behavior change comes with tests.
- No keys, tokens or private configuration in code, examples or issues.
- Keep documentation in Spanish and English: if you change one, update the other.
- Use [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).

### Pull requests

1. Create a branch from `main`.
2. Run the commands in the Development section; they must pass.
3. Open the pull request and fill in the template. CI must be green before merging.

### Reporting problems

Open an [issue](https://github.com/AvilaCarlosDev/contact-list-react-context/issues/new/choose). For vulnerabilities, follow the [security policy](SECURITY.md); do not post them in a public issue.
